# Python client design

- **Expose native, immutable domain values.**
  - The [root design](../DESIGN.md) defines shared semantics, RPC coverage, security, and verification.
  - Frozen records snapshot nested caller collections. Relationships hold persisted caveats; PermissionCheck holds evaluation context.
  - `ZedToken(value: str)` is an opaque immutable revision value. `str(token)` preserves every character, including empty strings. All consistency, watch, schema, delete, counter and materialize revision inputs and results use it; cursors remain separate.
  - ConsistencyMode names FULL, MIN_LATENCY, AT_LEAST and SNAPSHOT; token modes require nonempty tokens. Named fallback helpers treat None and empty tokens as absent.
  - Consistency is explicit: full(), min_latency(), at_least(token), snapshot(token), and named optional-token fallbacks.
- **Make behavior discoverable through enums.**
  - Tracing.DISABLED/ENABLED and LookupDebug.DISABLED/ENABLED independently select check tracing and lookup diagnostics.
  - Wildcards.DEFAULT/INCLUDE/EXCLUDE selects lookup wildcard behavior.
  - WatchContent.RELATIONSHIPS/CHECKPOINTS/SCHEMA selects the requested watch content collection.
  - SubjectRelationMode.ANY/DIRECT/NAMED backs the any(), direct() and named(name) relation-filter factories.
  - Unknown option values raise InvalidArgumentError before sending requests. Binary result facts remain booleans.
- **Keep sync and asyncio APIs equivalent.**
  - spicedb.sync.SpiceDBClient and spicedb.aio.SpiceDBClient share argument names and native results. Async unary calls are awaited; stream methods return AsyncStream directly.
  - Streams support explicit close/aclose and context managers, cancelling the actual call even during blocked iteration. Clients release their streams on close.
  - Aio clients bind to one event loop. Imports consume sync or async producers incrementally and cancel on producer failure or deadline.
- **Require explicit transport choices.**
  - Constructors default to TransportSecurity.TLS; TransportSecurity.PLAINTEXT enables plaintext.
  - RemoteCredentials.REJECT is the default; RemoteCredentials.ALLOW explicitly permits credentials on non-loopback plaintext hostnames and IP addresses through ordinary constructors and generated connect factories.
  - Custom CA and paired client certificate/key PEM support TLS and mTLS. TLS material with plaintext is rejected. raw_grpc() preserves authentication and client ownership.
- **Preserve authorization semantics and diagnostics.**
  - check uses the singular RPC; check_bulk chunks at 1,000, validates every echoed request and cardinality, and preserves each chunk revision and per-item error index.
  - Only unconditional permission grants satisfy has_permission and bool(result). Unknown and conditional results never grant.
  - Optional recursive native traces preserve schema, caveat evaluation, resolution presence, timestamps, durations and expiration.
- **Bound operations and preserve progress.**
  - Unary operations default to one 30-second monotonic budget shared by retries, chunks and pages; `default_timeout=DefaultDeadline.DISABLED` removes the default (a per-call `timeout` still applies; `None`, zero and negative values are rejected, never "disabled"). Streams/import accept explicit total deadlines without a default lifetime.
  - By default, idempotent reads retry UNAVAILABLE/ABORTED, at most three retries with full-jitter exponential backoff from 100 ms; streams retry only before delivery and watch never retries. `retry_policy=RetryPolicy(max_retries, retryable_codes, initial_backoff, max_backoff, on_retry)` changes that client-wide (any read code, including RESOURCE_EXHAUSTED), `retry_policy=Retries.DISABLED` turns retries off, and `stream_retries=StreamRetries.DISABLED` stops stream re-establishment alone. `call_options=CallOptions(retry_policy=...)` overrides the policy for one call, including that call's stream establishment (watch included, before its first event). Mutations never replay automatically; only a `write` holding only touches and no preconditions and `write_schema` may opt in per call, and deletes, delete-all, imports and counter registration raise `InvalidArgumentError` for an opt-in with retries before any request.
  - Bounded deletion (`DeletePartial.ALLOWED`, the default) requires a positive limit; `partial=DeletePartial.DISALLOWED` is all-or-nothing and may omit the limit to use the server default. Delete-all uses a separate positive page size, reports each acknowledged batch to `on_progress`, and attaches acknowledged progress to failures and cancellation.
  - Filters preserve Any, Direct and Named subject relations. JSON preserves null and rejects unsupported values with a field path.
  - Match the server's acceptance rules: an empty `write` is sent (SpiceDB evaluates its preconditions and returns the current revision); watch rejects `object_types` with `filters` because SpiceDB does; every schema read with a consistency field requires an explicit one (`min_latency()` matches the raw default).
- **Cover the protocol with native APIs.**
  - Schema reflection/diff, expansion, import/export, counters and materialize calls preserve native data and revisions. Experimental operations are named explicitly.
  - Materialize lookup preserves cursors and one bounded RPC; callers explicitly resume. Watch preserves every event variant and never reconnects automatically.
  - Lookup subjects bounds results locally with limit; page_size explicitly requests optional server pagination.
  - `paging=Paging.SINGLE_REQUEST` on `read_relationships` and `lookup_resources` sends exactly one request like the raw API: its limit is `limit` (unbounded without one; reads have none) and `page_size` is ignored.
- **Verify behavior and typed facades.**
  - Unit tests exercise sync/aio parity, transport security, cancellation, budgets, bulk echoes, token round trips and option validation.
  - Generated facades forward enums, tokens, contexts and results; fixtures are regenerated and checked with positive and negative type cases.

- **Make resource lookup grants explicit.**
  - `LookupPermissionshipFilter.ALL` is the default, preserving conditional results and missing context.
  - `LookupPermissionshipFilter.HAS_PERMISSION_ONLY` filters client-side to exact unconditional grants before yielding; unknown permissionship values never count as grants.
  - Limits count yielded matches. Skipped results advance cursors and further pages are fetched as needed.

- **Return explicit relationship write results.**
  - Transaction writes return immutable `WriteResult` values; access `result.revision` for the native `ZedToken` used by consistency and watch inputs.
  - Generated sync and async `touch`, `create`, `delete`, and `write` methods preserve the same `WriteResult` contract.
  - Serialization belongs to the revision token. The result itself is not accepted as a token.

- **Name non-atomic deletion explicitly.**
  - `delete_all_relationships_non_atomic` deletes matching relationships across individually transactional batches. The complete operation is non-atomic; completed batches remain deleted if a later batch fails.
  - Each nonempty response cursor is sent on the following request. Empty or absent cursors continue without a cursor.
  - `DeleteResult.revision` identifies the acknowledged revision. Failures expose acknowledged counts and the latest revision through `delete_progress`.

- **Watch through native relationship filters.**
  - Watch accepts full `Filter` values, including resource IDs or prefixes, relations, and direct or named subject relations. Multiple filters are ORed; empty filters watch all relationship changes.
  - Requests snapshot filter collections before streaming. Nonempty `object_types` and `filters` are mutually exclusive and rejected before transport work.

- **Expose native capabilities directly on generated clients.**
  - Generated sync and async clients explicitly forward every native public operation, including bounded and non-atomic deletion, watch filters, schema operations, imports/exports, counters, and materialize APIs.
  - Schema-aware check and lookup overloads retain subject constraints while exposing all native behavioral options. Typed writes accept typed or native transactions and preserve metadata.
  - Streams are returned directly, preserving identity, cancellation and context-manager ownership; async unary calls await the native result.

- **Serve tools and tests without the raw escape hatch.** How the root adoption rules are met:
  - Existing connection: `SpiceDBClient.from_channel(channel, *, default_timeout, retry_policy, stream_retries)` wraps a caller-owned `grpc.Channel` (sync) or `grpc.aio.Channel` (aio); the wrong flavor is rejected. There is no token, TLS or remote-credential parameter, because the channel carries its own credentials (for example `composite_channel_credentials(local_channel_credentials(), access_token_call_credentials(token))`); `close()` never closes it. Operation options apply.
  - Per-call transport options: every operation accepts `call_options=CallOptions(metadata, wait_for_ready, compression, response_metadata)`. Extra metadata is added to the client's own; an `authorization` entry is rejected on a client with a token. `ResponseMetadata` captures headers and trailers of the last attempt, on success and failure, and for streams once consumed or closed. Options apply to every attempt, chunk and page.
  - Protocol conversions: `spicedb.protoconv` exports `*_to_proto`/`*_from_proto` for objects, subjects, relationships, filters (Any/Direct/Named preserved), preconditions, updates, transactions (`WriteRelationshipsRequest`), consistency, tokens and contexts, and result conversions for checks with traces, lookups, reads, expand and writes. `check_bulk_to_proto(requests, results, context=)` rebuilds the whole bulk response (per-item errors as `google.rpc.Status`, the server's own when it sent one), `check_request_to_proto` the request item, and `lookup_subject_to_proto` also fills the deprecated top-level fields SpiceDB still sends; tests round-trip server responses through the client and back.
  - Errors: `SpiceDBError` subclasses `grpc.RpcError` and implements `code()`, `details()`, `trailing_metadata()` (a `grpc-status-details-bin` built from code, message and reason when no server trailers exist) and `initial_metadata()`, so existing `except grpc.RpcError` handlers and rich-status helpers keep working. Every class has a `grpc_code`; server errors keep the exact server code even without a dedicated class. `SpiceDBError.from_code(code, message, *, reason...)` builds the subclass a server error would produce. `code_of(exc)` classifies native errors, raw `grpc.RpcError`, `asyncio.CancelledError` (CANCELLED) and `TimeoutError` (DEADLINE_EXCEEDED). `server_message` holds the server's text verbatim (None for local errors); `str(error)` is that text.
  - Filter matching: `Filter.matches(relationship)` applies server semantics client-side.
  - Test double: `spicedb.testing.InMemoryClient` / `AsyncInMemoryClient` implement `write`, `check`, `check_bulk`, `read_relationships`, `delete_relationships`, `delete_all_relationships_non_atomic`, `import_relationships`, `export_relationships`, `read_schema`, `write_schema` and `reflect_schema` with the real clients' exact signatures (a test enforces it), SpiceDB precondition, CREATE-conflict, atomicity, import and delete-mode semantics, plus `set_check_result`, `set_reflect_schema_result`, `set_response_metadata` and `relationships()`. Errors match the real client's for the same failure: server failures via `from_code` (`server_message` set, `str()` the server text), local validation through the real clients' own request builders (`InvalidArgumentError`, no `server_message`), and the per-call retry opt-in rules. Options are plain keyword arguments and `CallOptions` fields, already inspectable, so there is no option-resolving API; the doubles honor read/export cursors, the export filter, delete limits and response-metadata targets.
  - Wrapper errors: not applicable. A bulk item error is the server's own error with `input_index` set, and delete-all progress is the `delete_progress` attribute of the original error, so `details()` reports the server message once.
  - Panicking constructors: not applicable. Python constructors raise `InvalidArgumentError` directly, so a constant or fixture is one expression (`Relationship.from_tuple("document:a#viewer@user:b")`) with no error value to unwrap; a `must_*` twin would be identical.
  - Observability: `str()` on `ObjectRef`, `SubjectRef`, `Relationship` (tuple syntax), `Filter` (zed-like, `*` for unset), `SubjectRelationFilter`, `Update`, `Precondition` and `Transaction`; `to_dict()` JSON-compatible forms on `Relationship`, `Filter`, `Update`, `Precondition` and `Transaction`; dataclass `repr` everywhere. `Transaction` holds native `Update`/`Precondition` values: `len(txn)` (so an empty transaction is falsy), `updates`, `preconditions`.
  - Short accessors: `Relationship.resource_type`, `resource_id`, `subject_type`, `subject_id`, `subject_relation`.
  - Tuple syntax: `Relationship.from_tuple(text)` and `str(relationship)` cover `[caveat]`, `[caveat:{json}]` and `[expiration:RFC 3339]`, round-tripping the fixtures `spicedb-gen/tuplecompat` checks against SpiceDB's parser; sub-microsecond expiration digits are truncated (Python `datetime`). `with_resource`, `with_relation` and `with_subject` copy a relationship, keeping caveat and expiration.
  - Bulk item errors: `check_bulk(item_errors=BulkItemErrors.RETURN)` puts each failing item's error (with `input_index`) on `CheckResult.error`; such a result is never a grant. `RAISE` stays the default.
  - Import: one call is one stream and one transaction; `batch_size` sets relationships per message. A server abort surfaces the call's final status (e.g. `AlreadyExistsError`), never a failed send or the request iterator's `GeneratorExit`.
  - Paging: `read_relationships` yields `ReadRelationship(relationship, after_result_cursor, read_at)`, `export_relationships` yields `ExportedRelationship(relationship, after_result_cursor)` (export responses carry no revision; every item of one response shares its cursor), and `LookupResource` gains `after_result_cursor` next to `looked_up_at`. Each accepts `cursor=` to resume with the same request and page size. Cursors are plain strings, a type distinct from `ZedToken`. Every page repeats the caller's consistency and one fixed page size; limits are enforced client-side, never by shrinking the last page.
  - Watch schema changes: `content=(WatchContent.RELATIONSHIPS, WatchContent.SCHEMA, WatchContent.CHECKPOINTS)` in any combination; `WatchEvent.schema_updated` reports the fact separately from `updates`.
  - Single protocol copy and legacy bridge: this client imports only spicedb-python-proto's modules (`authzed.api.v1.*_pb2`). spicedb-python-proto ships them as namespace packages with no shared `__init__.py`, and its `authzed-py-bridge` tool rewrites authzed-py to drop its own generated modules and require spicedb-python-proto, so `import spicedb` and the legacy `authzed.api.v1.Client` share one descriptor-pool copy in one process. An unbridged authzed-py installed beside this client overwrites the same files and is unsupported. See `../proto-clients/spicedb-python-proto/DESIGN.md`, "Canonical binding and the authzed-py bridge", and `MIGRATION.md`.
  - SpiceDB 1.30+ floor: features are native from SpiceDB 1.30. Data that older servers sent only in trailers (for example check debug traces) is reachable through `CallOptions(response_metadata=ResponseMetadata())`, not first-class API.
  - Legacy path and dependency floors: `MIGRATION.md` covers every observable change from authzed-py with before/after snippets. Runtime requirements are the lowest versions the suite passes against: `grpcio>=1.73.0` (older transports accept authority-bearing `unix:` targets that the loopback guard relies on the transport to reject), `protobuf>=7.36.2` (the bindings' gencode version) and `googleapis-common-protos>=1.56.1`; test tooling is only in the `dev` extra.
  - AI coding agents: `AI_INTEGRATION_GUIDE.md` shows the typed and native tiers with snippets type-checked against the current API and the generated sample fixture; the package docstring points to it.
