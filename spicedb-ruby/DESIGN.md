# Ruby client design

- **Use native, immutable domain values.**
  - The [root design](../DESIGN.md) defines shared semantics, RPC coverage, security, and verification.
  - Ruby 3.2+ exposes `ObjectRef`, `SubjectRef`, `Relationship`, `PermissionCheck`, and native result records. Nested collections are copied and frozen; `Transaction` is a mutable builder.
  - Names (types, relations, permissions, caveats) accept Strings or Symbols and object IDs accept Strings or Integers, converted with `to_s` (Ruby applications pass `permission: :view` and `record.id`). Any other type raises `InvalidArgumentError` naming the class received. Filters and lookup, expand and watch arguments convert the same way.
  - `to_h` on native values is deep: nested native values become Hashes, so `item.to_h[:relationship][:subject][:object][:object_id]` works as it did on a protobuf message hash. `ProtoConv.*_to_proto(...).to_h` gives the exact protobuf shape.
  - `ZedToken.new(string)` snapshots an opaque string and `to_s` preserves it losslessly. Every public revision input and result uses `ZedToken`, with `nil` representing absence. Cursors remain separate values.
  - Consistency is required on reads: `full`, `min_latency`, `at_least(token)`, or `snapshot(token)`. Named fallback helpers use `nil` to select their fallback.
- **Make behavioral choices discoverable and validated.**
  - `Tracing::DISABLED` and `Tracing::ENABLED` select singular and bulk diagnostics, defaulting to disabled. Full recursive native traces preserve absent values and unknown server states.
  - `watch(content: [WatchContent::RELATIONSHIPS])` accepts explicit relationship, checkpoint, and schema selectors. Invalid cases fail before transport calls.
  - `TransportSecurity::TLS` is the constructor default; `PLAINTEXT` explicitly selects plaintext. Named TLS factories support default trust, custom CAs, and mTLS.
  - `RemoteCredentials::LOOPBACK_ONLY` rejects remote plaintext credentials; `ALLOW_PLAINTEXT` explicitly permits them through `new_plaintext(remote_credentials: ...)` and the normal constructor. TLS material is rejected with plaintext.
- **Preserve authorization meaning and caller data.**
  - `CheckResult#has_permission?` grants only unconditional permission; Ruby object truthiness is not an authorization predicate. Unknown states remain distinct.
  - Bulk checks validate cardinality and echoed requests, chunk at 1,000, and retain each chunk's revision and each error's absolute input index.
  - Item context overrides call context by key. JSON types and null survive conversion; unrepresentable data raises a typed field-specific error.
- **Bound operations and release resources deterministically.**
  - Unary operations share a 30-second default budget (`default_timeout:`) across attempts, backoff, chunks and pages; `default_deadline: DefaultDeadline::DISABLED` removes the default while a per-call `timeout:` still applies. Streams accept explicit total budgets and otherwise remain unbounded.
  - By default, idempotent reads retry UNAVAILABLE and ABORTED up to three times with full-jitter backoff from 100 ms. `retry_policy: RetryPolicy.new(max_retries:, retryable_codes:, initial_backoff:, max_backoff:, on_retry:)` replaces it client-wide (a caller may opt into RESOURCE_EXHAUSTED; `on_retry` receives a `RetryEvent`), `retries: Retries::DISABLED` turns retries off, and `stream_retries: StreamRetries::DISABLED` stops stream re-establishment (watch never re-establishes by default). Every operation's `retry_policy:` overrides the client's for that call, including stream establishment (a per-call policy also lets one watch re-establish, and `RetryPolicy.new(max_retries: 0)` exempts one call). `operation_retry_policies: { watch: RetryPolicy.new(max_retries: 0) }` on the client sets the policy for every call of one operation (keys from `Client::OPERATIONS`, method names); the most specific wins: per call, then per operation, then client-wide (including under `Retries`/`StreamRetries::DISABLED`). `Transaction#idempotent?` (touch-only, no preconditions) is the retry-eligibility rule; a `:write` entry retries only idempotent transactions and leaves others unretried without an error, and `Client::NEVER_IDEMPOTENT_OPERATIONS` (deletes, delete-all, imports, counter registration) reject an entry with retries when the client is built. Ruby's per-call option is a plain keyword and value, so callers abstract over it without a generic constraint. Mutations are never replayed automatically; only a touch-only `write` without preconditions and `write_schema` may opt in per call, and every other mutation raises `InvalidArgumentError` for the opt-in before any request. Streams never restart after exposing an item.
  - Closeable `Stream` values and block consumption release the underlying RPC, including blocked reads. Imports consume incrementally and cancel on producer failure; `batch_size:` sets relationships per message, one call is one stream and one transaction, and an aborted stream raises the server's final status (for example `AlreadyExistsError`), never a transport send failure.
- **Keep filters and deletion exact.**
  - Subject relation filters distinguish Any, Direct, and Named. Exact relationship filters preserve tuple identity.
  - `delete_relationships` sends one request. In the default `partial: DeletePartial::ALLOWED` mode it requires a positive `limit:`; `DeletePartial::DISALLOWED` is all-or-nothing (the server rejects a delete exceeding its limit with INVALID_ARGUMENT) and `limit:` may be omitted for the server default. Delete-all uses a separate positive page size and reports each acknowledged batch's cumulative `DeleteResult` to `on_progress:`. Unknown completion states raise errors.
  - Interrupted deletion retains cumulative acknowledged counts, latest token, and cursor, including malformed final responses. Multiple pages are not atomic.
- **Cover the protocol with native results.**
  - Schema inspection, reflection, diffs, expansion, watch, import/export, counters, and experimental materialize APIs use native values.
  - Watch preserves transaction and revision metadata. Materialize streams preserve variants, changes, permission sets, cursor state and revisions; download results expose file metadata without fetching files.
  - Typed errors retain original causes and structured server details (see "Interoperate with grpc-ruby errors"). `proto_client` exposes the same authenticated connection as a secondary escape hatch with shared ownership.
- **Verify observable behavior.**
  - Tests cover immutable values, option validation, token propagation, strict bulk echoes, cumulative deletion, real TLS handshakes, cancellation, and deadlines.
  - Maintained examples assert behavior and use named choices; `bundle exec rspec` and `bundle exec rubocop --cache false` validate changes.

- **Make resource lookup grants explicit.**
  - `LookupPermissionshipFilter::ALL` is the default, preserving conditional results and missing context.
  - `LookupPermissionshipFilter::HAS_PERMISSION_ONLY` filters client-side to exact unconditional grants before yielding; unknown permissionship values never count as grants.
  - Limits count yielded matches. Skipped results advance cursors and further pages are fetched as needed.

- **Return explicit relationship write results.**
  - Transaction writes return immutable `WriteResult` values; access `result.revision` for the native `ZedToken` used by consistency and watch inputs.
  - Serialization belongs to the revision token. The result itself is not accepted as a token.

- **Name non-atomic deletion explicitly.**
  - `delete_all_relationships_non_atomic` deletes matching relationships across individually transactional batches. The complete operation is non-atomic; completed batches remain deleted if a later batch fails.
  - Each nonempty response cursor is sent on the following request. Empty or absent cursors continue without a cursor.
  - `DeleteResult.revision` identifies the acknowledged revision. Failures expose acknowledged counts and the latest revision through `delete_progress`.

- **Watch through native relationship filters.**
  - Watch accepts full `Filter` values, including resource IDs or prefixes, relations, and direct or named subject relations. Multiple filters are ORed; empty filters watch all relationship changes.
  - Requests snapshot filter collections before streaming. Nonempty `object_types` and `filters` are mutually exclusive and rejected before transport work.
  - `content:` including `WatchContent::SCHEMA` requests schema-change events, combinable with `WatchContent::CHECKPOINTS`; `WatchEvent#schema_updated` reports them separately from relationship updates.

- **Be one copy of the protocol bindings.**
  - `spicedb-proto` is the canonical Ruby binding for `authzed.api.*`, under the same require paths the official `authzed` gem uses. Its `bridge/authzed_bridge.rb` rewrites an `authzed` checkout to drop its generated files and depend on `spicedb-proto`; a second, unbridged copy raises `SpiceDBProto::BindingConflictError` at load time. See the proto tier's DESIGN.md, "Canonical binding", and MIGRATION.md.
  - Native support starts at SpiceDB 1.30. Older servers' trailer-only data is reachable through `call_options:` response metadata, not first-class API.

- **Interoperate with grpc-ruby errors.**
  - `SpiceDB::Error` subclasses `GRPC::BadStatus`, so existing `rescue GRPC::BadStatus => e` code catches native errors and `e.code` is the matching `GRPC::Core::StatusCodes` value: the server's code for server errors, the class's code for local errors (`InvalidArgumentError` is INVALID_ARGUMENT, an exhausted budget is DEADLINE_EXCEEDED) and for errors built by callers. Codes without a dedicated class keep their code on `SpiceDB::Error`. `to_status`/`to_rpc_status` work; `metadata` holds a server error's trailers.
  - `message` is the display message; `server_message` is the server's status message verbatim (for local errors, the display message, so it always has a value); a mapped error keeps the original as `cause`.
  - There are no wrapper errors: a bulk item's error is the item's own error with `input_index`, and interrupted deletion attaches `delete_progress` to the failure itself, so `message` and `to_status` report the server's message once.
  - `SpiceDB::Error.from_code(code, message)` builds the matching class for test doubles. `SpiceDB.code_of(err)` and `SpiceDB.error_class_of(err)` classify native errors, raw `GRPC::BadStatus` and `Google::Rpc::Status`. Ruby has single inheritance, so native classes cannot also subclass grpc's per-code classes; instead the library extends `===` on each of them (`SpiceDB::GrpcCodeMatch`) to match a native error with that code, so `rescue GRPC::AlreadyExists` catches `SpiceDB::AlreadyExistsError` (and `case`/`when` agrees). Raw grpc errors match exactly as before; `is_a?(GRPC::AlreadyExists)` stays false. MIGRATION.md states the interop.

- **Serve tooling without the raw escape hatch.**
  - `Client.from_channel(channel, interceptors: [], **options)` wraps a caller-owned `GRPC::Core::Channel`. The channel carries its own transport security; call credentials for a plaintext channel go in `interceptors` (for example `SpiceDBProto::BearerTokenInterceptor`). Operation options apply. `close` releases this client's streams and never closes the channel.
  - Every operation accepts `call_options: CallOptions.new(metadata:, credentials:, response_metadata:)`: request metadata and call credentials on every attempt, page and chunk, and a `ResponseMetadata` that captures the last request's headers and trailers (also on failure).
  - `SpiceDB::ProtoConv` exports native<->protocol conversions for objects, subjects, relationships, filters, preconditions, updates, consistency and tokens, check requests, and the results tools print (check results with recursive traces, lookups, expand trees, write results, read items, watch events). `protoconv.rb` loads the protocol bindings itself, so every conversion works right after `require 'spicedb'`, before any client exists.
  - `check_bulk(item_errors: BulkItemErrors::RETURNED)` puts each failed item's error, with its absolute `input_index`, on `CheckResult#error`; an errored item has `:unspecified` permissionship and never grants. `BulkItemErrors::RAISED` (default) fails the call.
  - Paged reads yield `ReadRelationship` (`relationship`, `cursor`, `read_at`) from `read_relationships`, `ExportedRelationship` (`relationship`, `cursor`; exports carry no revision) from `export_relationships`, and `LookupResource#cursor` from `lookup_resources`. Items delegate relationship readers (`resource_id`, `subject_id`, `to_s`, ...) and `Transaction` accepts them. `cursor:` resumes; resuming requires repeating the request and page size. Every page repeats the caller's consistency and one fixed `page_size:` (SpiceDB hashes both into the cursor, which pins the revision); a total `limit:` is enforced client-side. `paging: Paging::SINGLE_REQUEST` on `read_relationships` and `lookup_resources` sends one request like the raw API (limit is `limit:` or unbounded; `page_size:` ignored).
  - `ProtoConv.check_bulk_to_proto(checks, results, context:)` rebuilds a whole bulk-check response (per-item errors as `google.rpc.Status` with their ErrorInfo, `checked_at` from the last item), with `check_bulk_request_item_to_proto` and `status_to_proto`; `lookup_subject_to_proto` fills the deprecated top-level fields SpiceDB still sends.
  - `write` sends empty transactions (SpiceDB checks their preconditions and returns the current revision). Watch rejects object types with filters because SpiceDB does. Schema reads other than `read_schema` (whose request has no consistency) require `consistency:`; `Consistency.min_latency` matches the raw default.

- **Make native values observable and testable.**
  - `ObjectRef`, `SubjectRef`, `Relationship`, `Filter`, `SubjectRelationFilter`, `Update`, `Precondition` and `Transaction` have readable `to_s`; relationships, updates, filters, preconditions and transactions have `as_json`/`to_json` diagnostic forms (no parser). `Transaction#updates`/`#preconditions` return frozen `Update`/`Precondition` values; `Transaction#length`/`size` count updates without copying.
  - `Filter#matches?(relationship)` applies SpiceDB's filter semantics client-side, including Any/Direct/Named subject relations; caveats and expiration never affect matching.
  - `require 'spicedb/testing'` provides `SpiceDB::Testing::Store`, an in-memory double whose `write`, `read_relationships`, `delete_relationships`, `import_relationships`, `export_relationships`, `read_schema`, `write_schema`, `reflect_schema`, `check` and `check_bulk` have the client's exact parameters and results: preconditions, CREATE conflicts and atomic transactions and imports, filtered reads, exports and deletes (including all-or-nothing) with cursors and limits, schema text, reflection registered with `set_reflect_schema_result`, checks and lookups (below), and `call_options:` response metadata from `set_response_metadata`. Its errors match the client's for the same failure: server failures carry the server's code and message (as `message` and `server_message`, with SpiceDB's reason), local validation raises `InvalidArgumentError` (its `server_message` is its message), and non-idempotent mutations reject a `retry_policy:` opt-in. It records every call as a `Testing::Call` (`operation` method name, per-operation `index`, positional `request`, and `options`: every keyword as bound, defaults included) through `calls`/`calls_of`, and `fault_hook=` receives a `Testing::Fault` at `FaultStage::CALL`, `IMPORT_BATCH` (batch index of the call's `batch_size:`), `IMPORT_COMMIT` and `ITEM` (read/export/lookup item index), raising the exception it returns; a failed write or import applies nothing. `fail_next(operation, error)` fails exactly one call and `Store.server_error(code, message, reason:)` builds client-shaped errors. Reads and exports return a re-iterable `Enumerator` so a fault can interrupt them after some items. At `IMPORT_BATCH`, `Fault#batch` holds that batch's relationships. `Store.cursor_after(n)` builds the cursor the store puts on item `n` (its format, `n` in decimal, is stable for tests), and `read_schema_revision = SchemaRevision::OMITTED` makes `read_schema` report a nil revision.
  - Ruby has no static interfaces, so the client's interface is its public method set: a spec asserts that `Testing::Store` defines every public `Client` method with identical `parameters`, and `Store::OPERATIONS` is `Client::OPERATIONS`. `delete_all_relationships_non_atomic` and `close` work in memory (`proto_client` is nil); every other operation without in-memory semantics (watch, expand, schema introspection, experimental) is recorded, consults the fault hook, validates its retry policy, and raises `SpiceDB::Error` with code `UNIMPLEMENTED` (streaming operations when iterated).
  - The double does not evaluate the schema: a permission defined as `reader + writer + parent_folder->read` is granted only by a stored relationship with the permission's exact name or by the check resolver. Its docs (class comment, README, AI guide) direct permission-logic tests to the resolver or to SpiceDB `serve-testing`.
  - The double resolves a check in the root order: a result registered with `set_check_result`; then `check_resolver` (a callable receiving the `PermissionCheck` with call-level context merged under its own, returning a `CheckResult`, a permissionship Symbol, `true`/`false`, or `nil` to decline; `Store::GRANT_ALL` grants everything; failures come from the fault hooks); then stored relationships on the resource whose relation is the permission's name and whose subject matches exactly or by wildcard (a wildcard matches only direct subjects of its type; a caveated match is conditional, an uncaveated one wins, an expired one never grants); else `:no_permission`. `lookup_resources` and `lookup_subjects` enumerate objects of the requested type in first-appearance order across stored relationships (as resource or subject), return those resolution grants (conditional ones with `partial_caveat`), honor `permissionship_filter:`, `limit:` and `cursor:` (cursors count granted results, including ones the filter drops; `lookup_subjects` has no cursor, like the client), return a stored wildcard subject as `*`, and run the `ITEM` fault hook before each result.
  - Options are plain keyword arguments and value objects (`RetryPolicy`, `CallOptions`, `Paging`), already inspectable by a test double or wrapper, so Ruby has no option-resolution helper.
  - No panicking constructor variants: Ruby constructors already raise `InvalidArgumentError`, so `Relationship.from_tuple("...")` is the one-line constant/test form.
  - `Relationship#resource_type`, `#resource_id`, `#subject_type`, `#subject_id` and `#subject_relation` shorten the common paths; `with_resource`, `with_relation` and `with_subject` copy a relationship.
  - `Relationship.from_tuple`/`#to_s` cover SpiceDB's full syntax: `[caveat]`, `[caveat:{json}]` (keys sorted on output) and `[expiration:RFC3339]` (UTC, fractional seconds only when nonzero), and `...` as a direct subject. Specs use the vectors spicedb-gen/tuplecompat checks against SpiceDB's parser, and the `tooling_escape_hatches` example round-trips caveats and expiration through a live SpiceDB.

- **Share one client per process, and survive forks.**
  - `SpiceDB::Client` is safe for concurrent use from many threads; one per process is the intended shape (a spec and an example run many threads on one client). Its stream and connection bookkeeping is guarded by a Mutex.
  - The client validates its endpoint and TLS material at construction (`SpiceDBProto::Client.validate_connection!`) but opens its gRPC channel on first use, in the calling process. A client built before a fork therefore works in each child if the parent made no call. gRPC refuses use in a child once the parent has used it, so a call in a child of a parent that connected raises `ForkedClientError` (FAILED_PRECONDITION) naming the fix, unless grpc's fork support is enabled (`GRPC_ENABLE_FORK_SUPPORT=1` on Linux), in which case grpc carries the channel. A new client built in such a child raises `ForkedClientError` too, rather than grpc's untyped RuntimeError: the library records the first process that opened a channel through any client (`SpiceDB.grpc_used_pid`, inherited across fork) and, for gRPC use it could not observe, maps grpc's fork refusal to the same error. `close` in a child never closes the parent's channel. Because the client is lazy, `connect!(timeout:)` is its startup readiness check (root DESIGN.md: clients that connect lazily offer one): it opens the connection in the calling process and waits for the channel to be ready, raising `UnavailableError` (the channel failed to connect) or `DeadlineExceededError` (still connecting) at the timeout. Under a forking server it runs in each worker, never the master; the test double's `connect!` is a no-op. README.md, "Concurrency and forking", has the Rails initializer and Puma `on_worker_boot` placement.

- **Document migration and dependencies.**
  - `README.md` covers installation from a checkout, a first call, and concurrency and forking. `MIGRATION.md` opens with a Requirements section (Ruby >= 3.2, grpc >= 1.73, google-protobuf >= 3.25, googleapis-common-protos-types >= 1.11; a spec keeps it in step with the gemspecs), has a legacy-to-new member table, and covers moving from the `authzed` gem; `AI_INTEGRATION_GUIDE.md` is the concrete guide for coding agents, with every snippet executed against a live SpiceDB. No typed generator exists for Ruby, so spicedb-gen rules do not apply.
  - The gemspecs declare the lowest working runtime versions (`grpc >= 1.73`, `google-protobuf >= 3.25`, `googleapis-common-protos-types >= 1.11`); rspec and rubocop are development dependencies, which consumers never install. Ruby has no mechanical API-compatibility gate; specs and review cover compatibility.
